# TRMNL docs: verbatim excerpts (fetched 2026-09-29)

Re-fetch before relying on these. Pages fetched with curl (help centre, docs.trmnl.com raw Markdown, trmnl.com/framework).

## Webhooks: https://docs.trmnl.com/go/private-plugins/webhooks.md

> You may send data to TRMNL's server up to 12x per hour. TRMNL+ subscribers may send up to 30x payloads per hour.

> You may send up to 5kb of data. TRMNL+ subscribers may send up to 10kb of data. Larger payloads receive a `422` response with the size we measured.

> Webhooks with a transform accept up to 1mb, and the transformed result must fit the limits above.

## Private plugins (polling): https://help.trmnl.com/en/articles/9510536-private-plugins

> If you choose Polling, TRMNL will fetch this content on your behalf.

> Polling URLs may be of content type JSON, RSS, XML, plaintext, or CSV. They may access values from custom form fields via {{ form_field_keyname }} interpolation.

> Fastest Refresh Rate: You can specify the fastest refresh rate you will allow for users who install your plugin

> By default, our backend skips generating screens if the merge variables are the same between requests.

(No payload size limit for polling is stated on this page.)

## Dynamic polling URLs: https://help.trmnl.com/en/articles/12689499-dynamic-polling-urls

## Refresh rates: https://help.trmnl.com/en/articles/10113695-how-refresh-rates-work

> On-demand refresh was enabled for all users by the end of May, 2026. [...] your device requests a screen and our servers anticipate that request and ensure data is fresh and a new screen is ready.

> By default, accounts have a 15 minute minimum refresh rate. With TRMNL+, this can be as low as 5 minutes.

> If the underlying data for a plugin [...] has not changed then the screen will not be generated.

## On-demand refresh: https://help.trmnl.com/en/articles/15123293-on-demand-plugin-refresh

> This improvement was released to all users on May 22, 2026. [...] Plugins are automatically refreshed right before they are shown on the TRMNL.

> Now that setting has been repurposed to have a new meaning: it's the minimum plugin refresh rate.

## Saved state: https://help.trmnl.com/en/articles/16777795-saved-state

> A private plugin using the Polling, Static or Webhook strategy. Async Polling never runs a transform, so it cannot use saved state.

> Your Polling URL, headers and body are all templated, so a saved cursor can go straight into the request.

> There is a limit of 8192 bytes.

> You installed someone else's recipe and expected their data. State belongs to your install, not to the recipe.

## Framework releases: https://trmnl.com/framework/releases

> Framework v3.4.0 Released on 2026-09-28. [...] The current docs track is 3.4. Links to /framework/docs/3.3/... redirect to it.

> Framework v3.3.0 Released on 2026-08-27. Framework 3.3 brings maps to plugins. [...] TRMNLMaps ships inside the runtime and builds a MapLibre GL JS style out of framework paint over OpenStreetMap vector tiles [...] What it draws is one still frame, with no interaction and no animation.

> Four presets ship: streets, minimal, outline and blank. Plot your own data with route(), dot(), fit() and decodePolyline()

> MapLibre GL JS is a plugin dependency, not a framework one. A map plugin loads https://trmnl.com/js/maplibre-gl/5.24.0/maplibre-gl.js and its stylesheet with classic tags

> Framework 3.3 is backward compatible with 3.0, 3.1 and 3.2

> The terminalize pass now ends by waiting for every attached map to go idle, a bounded TRMNLMaps.settle(), so TRMNL_PLUGINS_READY fires only once the tiles, the widened lines and the labels have drawn.

## Map (docs 3.4): https://trmnl.com/framework/docs/3.4/map

> A map that names no tile source fetches TRMNL's own tiles (maps.trmnl.com) itself, and whoever renders the plugin pays nothing.

> route(map, coords, { el, width }) and dot(map, lngLat, { el, radius, hollow }): plot a route and its markers as crisp fills painted from the screen's chart-series ramp.
> fit(map, coords, { padding, maxZoom }): frames the coordinates on an integer zoom, with no animation.
> decodePolyline(str): a Google encoded polyline (the shape Strava returns) as [lng, lat] pairs.

> Maps are built non-interactive. [...] set the camera in the options or with fit(), never with flyTo or easeTo.

> watch() and attach() place a framework-styled "© OpenStreetMap contributors" label on every map: keep it.

> The bottom right corner belongs to the data credit, which has to stay visible.
