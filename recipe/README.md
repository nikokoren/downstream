TRMNL markup, BRIEF §8: full, half_horizontal, half_vertical, quadrant (Framework 3.4, D18), portrait in every view. No literal words in templates (R13) except the error screen (TEXT_REQUIREMENTS). Design: `docs/DESIGN_PHILOSOPHY.md`, D19–D21.

## Files

- `src/`: the plugin in TRMNL's private-plugin export layout.
  - `settings.yml`: name, Polling strategy, the Polling URL, and the form fields (About This Plugin with the data credits (D20), Region Europe/USA/Canada as a multi-select with none or all ticked = a mix (D22, D23), Language en/de, Units Metric/Imperial, metric by default).
  - `shared.liquid`: goes in the **Shared** tab. Reads the two settings (an empty value counts as the default), defines the `ds_chain`, `ds_box` and `ds_error` templates, and one map script that allows several copies on a screen (mashups).
  - `full.liquid`, `half_horizontal.liquid`, `half_vertical.liquid`, `quadrant.liquid`: one per view. Each is a full-bleed map (`TRMNLMaps`, `outline` preset, integer zoom fitted to the whole path, D19) with the text box bottom left (D21).
- `polling_url.liquid`: the recipe's Polling URL (D18); it picks the folder for the ticked regions (`eu/`, `us/`, `ca/`, `eu-us/`, `eu-ca/`, `us-ca/`, `mix/`) and `/p/` when Explore drainage divides is enabled, otherwise `/t/`. `p/<n>.json` is `t/<n>.json`'s town with its companion (D25, `pipeline/downstream/companions.py`), so both use the same slot counts. Generated by `pipeline/downstream/site.py`.
  with fixed slot counts per folder (eu 5,400, us 2,900, ca 260, eu-us 8,250, eu-ca 5,650, us-ca 3,150, mix 8,500, since 2026-10-15; not the town counts, which

## Render check

Needs `uv run python -m downstream.fetch framework` (Framework 3.4.0 CSS/JS, fonts, MapLibre 5.24.0 into `data/raw/framework/`) and a built site (`python -m downstream.site`).

```
cd recipe/tools && npm ci && npm run check                  # quick check, after each change (~5 min)
npm run check:full                                          # every case, only before shipping a version
ONLY=Munich VIEW=full DEVICE=x_land npm run check:full      # a subset (also JOBS=n, DEBUG=1)
```

The quick check (author 2026-09-30: after each change) renders every view on OG 1-bit and X landscape for Munich, Iisalmi, Saint-Quentin-en-Yvelines, Cambridge, Hibbing and Calgary, in both languages: 96 cases. The full check renders every view (inside a real mashup for the smaller ones) on OG 1-bit, OG 2-bit, X landscape and X portrait, for 20 towns picked for their edge cases (among them Vihti, Hafnarfjordur's 0.3 km path and the two longest town lines) plus the error screen, in English/imperial and German/metric. Liquid is rendered by `render.rb` with Ruby Liquid (`gem install liquid`; 5.14.0 checked), the engine TRMNL runs; liquidjs, used at first, accepted a tag TRMNL rejected. Maps use Chromium's software WebGL. A case fails when:

- a map is missing, not built or not fully drawn, or its path isn't painted (the screenshot has no ink at 10 % or more of the visible path points);
- the path runs off the map or under the text box;
- the box leaves the map or covers the map's OpenStreetMap credit;
- text is cut (the Framework's clamp trimmed it, or it overflows). Exception: town lines over 45 characters (4 towns in German, 1 in English, 2026-10-15) may be shortened; they are counted, not failed.
- a case throws (Liquid error, timeout).

Screenshots and `results.json` go to `tools/out/` (git-ignored). TRMNL's tiles, glyphs and styles are fetched once by Node and cached in `data/cache/trmnl-maps/`, since Chromium's own fetches through the sandbox proxy failed and left maps half drawn. Before checking, it calls `TRMNLMaps.refresh()` as TRMNL's screenshot service does.

## Globe view

The optional **Globe view** boolean (`world_map`, off by default) adds the same town-centred globe
as Ridgelines to full-screen landscape and portrait views. It has outlined coastlines, a solid
centre dot, and a circular canvas halo. It is larger on TRMNL X. The portrait text box narrows to
leave room, and route framing keeps the whole river path clear of both the text and the globe.
Half views and quadrants do not show it. Existing town payloads already carry the coordinates;
no data rebuild, new API or extra asset request is needed.

The bundled Natural Earth 1:110m land is public domain. The projection uses d3-geo 3.1.1 and
d3-array 3.2.5, with their notices retained in Shared and `tools/globe-LICENSE.txt`. It magnifies
the centre up to 3x while keeping the hemisphere's rim fixed, the same deliberately stylised
locator as Ridgelines. Regeneration instructions are in `tools/globe.js` and `tools/world_map.py`.

After installing the updated Shared and view templates, add the `world_map` field from
`src/settings.yml` and enable it in the plugin's settings. The default preserves existing installs.

The committed Munich fixture supports a small preview without building the regional dataset:

```
node recipe/tools/test_globe.mjs
CHROME=/usr/bin/chromium WORLD_MAP=both UNITS=all node recipe/tools/render-check.mjs --preview
```

Run these from the repository root with Ruby and Liquid 5.14.0 installed, the npm dependencies
installed in `recipe/tools`, and the Framework/MapLibre/font assets cached as above. The preview
checks all four layouts on OG 1-bit/2-bit and X 4-bit in both orientations, both languages, both
units, globe on/off. It exercises one real route, not the full town corpus. To broaden projection
coverage, the geometry test optionally accepts JSON files containing real `entries` with lat/lon.

`OFFLINE_BASEMAP=1` explicitly substitutes bundled Natural Earth coastlines for hosted vector
tiles. Use it only for offline layout/geometry checks; it does not validate hosted tile loading.
The production recipe always keeps its normal TRMNL outline basemap. `DS_RENDER_OUT` can isolate
review runs; `DS_RECIPE_SRC` and `DS_PREVIEW_PAYLOAD` allow draft template/payload variants.

**Map labels** (`map_labels`) controls town and river-change callouts in all views and is on
by default. The text boxes and route markers remain visible when it is off.
Town names and named river hand-offs are drawn by Shared in the normal views. New pipeline
builds export their source coordinates as `changes`; older packets still show the town name.
With **Explore drainage divides** (`watershed_pairs`) enabled, Full accepts a two-route packet and
reuses `ds_box` for both bottom-edge cards, including
the complete sentence, river chain, destination, distance and estimated travel time. Both routes
use matching ink and markers, with no letter key or destination callouts.

The setting is off by default and applies only to Full. Smaller layouts, and Full with it off,
show the primary town from a paired packet. A normal town packet also works with it on.
There is no heading above the map. The quadrant can use three town/destination lines and two
distance/time lines when needed, keeping the primary journey readable in portrait.

[Pair selection](../docs/PAIR_SELECTION.md) records the 6,168 candidates at 80 km across the
existing eligible town pool. The feed builder requires source-basin/start-reach/routing
checks, distinct basins/outlets and a ≤6,144-byte paired packet. It uses the 15-minute cadence,
fills sparse pools with normal town slots, and preserves pair assignments across builds to
keep a three-day minimum pair cooldown. Comparisons use exactly the normal recipe town
classification, including D24. Source-data execution is complete: **1,705 European and 630
US pairs** pass; Canada currently falls back to ordinary journeys. The feed is built locally
and has not been deployed. See [verification](../docs/PAIR_VERIFICATION.md) and
[feed implementation](../docs/PAIR_FEED.md).
Run `uv run python -m downstream.pairs --help` in `pipeline/` for the search tool;
`node recipe/tools/test-pair-mode.mjs` verifies the Full-only gate.

The [comparison notes](../docs/WATERSHED_BATTLE.md) document the packet, fixtures and remaining
data limits. The published recipe is unchanged; the local polling URL now includes the feed
switch. Nürnberg in the historical review
still uses explicitly marked reference geometry and has no captured duration; the card marks
that value unavailable. The earlier [walkthrough](../docs/UX_CONCEPTS.md) records superseded ideas.

Map callouts are maintained in `tools/map-labels.js` and bundled into Shared for the TRMNL
editor. After editing them, run `node recipe/tools/bundle-map-labels.mjs` from the repo root;
`--check` verifies that the bundle matches. `battle-preview.mjs` renders the actual full template
for both normal and paired packets; `battle-gallery.mjs` builds an optional small review board
with one external PNG loaded at a time. The plain `watershed-pair-v4.png`,
`watershed-pair-portrait-v4.png` and `normal-labels-v4.png` are the preferred review artifacts.

The collision checks in `render-check.mjs` inspect actual SVG boxes/connectors against both
river paths, markers, other callouts and native background names. Crowded river-change labels
can be omitted; the cards retain the chain. Starting towns are planned together and can use a nearby
label without a connector at clustered starts. Conflicting native city names are hidden after
the Framework places them. Connecting strokes are clipped around rivers and markers, so a
necessary town connector cannot overwrite a river loop. Full reserves annotation space around the route bounds. Current
collision-review PNGs are under `tools/out/label-clearance/`.
`node recipe/tools/check-map-labels.mjs` replays every accepted pair in both languages on the
OG portrait frame using actual Liquid cards, Framework fonts and a blank MapLibre projection.
`DS_LABEL_FRAMES=all` adds the other three distinct Full frames; `DS_PAIR_LIMIT=n` limits the
sample. This checks town-label retention; hosted-map geometry/pixels are checked separately
by `render-check.mjs`.

## Installing (not confirmed on TRMNL yet)

Create a private plugin with Polling strategy, paste the Polling URL, then paste each `.liquid` file into its tab (Shared, Full, Half horizontal, Half vertical, Quadrant) and add the form fields from `settings.yml`. Alternatively, zip `src/` and use TRMNL's plugin import; that path hasn't been tried.
